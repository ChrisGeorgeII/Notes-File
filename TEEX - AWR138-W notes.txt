	NAT and PAT firewalls
		Network address Translation (NAT)
			combines NAT component and traditional SPI firewall
			keeps track of a pool of IPv4 address and associats a public address with each system as it request access to the internet
				when attempting to transmit data to internet, Nat performs a "translation" inserting the public address associated with that host iunto the IP header.
		Port Address Translation (PAT)
			allows multiple computers to utilize the internet simultaneously using a single public IP address
	limitations and complications of network addresses
		IP address	-	four sets of 3 digits each separated by periods, each set of 3 digits is called an octet, each octet range from 0 to 255

		# of IP address

			ip addresses are allocated/assigned in blocks reffered to Class A, Class B, and Class C
			each block of address in a givven class consist of consecutive addresses totaling:
				Class A = 16,777,216 addresses
				Class B = 4,048,576
				Class C = 65,536
		# of Public IP addressesconnected devices

	TCP/IP and PAT
		TCP
			IP identifies each system in a connection by associating the hardware [MAC] address with an IP address
				TCP identifies applications on these systems that are communicating by usilizing ports.
			remote
				on the private side of a PAT device when a device wants to connect to a remote system, the device constructs an ordinarry TCP segment, contained in an IP packet
					the TCP header contains both destinations and source port numbers
						for most communications the destination port number will be a port number (80 for HTTP, 25 for SMTP, etc...) when source port number will be a random number grater than 1024
							similar to port remapping it involves changing the port number used for certin types of communications on a system
								when remapping, a PAT device can hide the real port number of an internal application from the outside world.
				PAT device can Uniquely Identify every connection running on a network.
			headers
				on the private side of a PAT device, the Pat takes the TCP segment and changes the headers.
				Source IP address is changed from private IP address that the host submitted, to global IP address being shared by the PAT device.
				Source TCP port may be changed depending on the implementation on whether or not another PAT decided to use that TCP port.
			segment
				"after changing these items" the PAT sends the segment to its original destination
					Neither the server nor the host on the private side of the PAT firewall knows that the PAT is in use.
					is possible to tell when host is using a PAT device, "look for clues"
			response
				When Server sends data back to client, PAT device receives, looks at what server sent the segment, what destination port, forward the segemnt to proper host
					similar to how internal port number is hidden, a PAT device hides internal hosts from outside attackers using the private addresses.
			TCP
				Majority of the Network Traffic found on the internet utilizes Transmission Control Protocol (TCP) over the Internet Protocol.
					PAT takes advantate of these protocols allowing multiple computers to use the same Public IP Address
				all systems on the private side of a PAT device have private IP addresses
				NAT and PAT are highly similar
	Security of NAT/PAT firewalls
		Nat and PAT firewalls offer some defence over traditional firewalls
			NAT/PAT device receives a TCP segments for a Public IP address on a network, examins the segment and carrys out one of the following:
				if segmentis part of a known ongoing TCP connection, forward segment to proper system on the inside of the network
				if segment is a new connection request, looks at its forwording table; if it finds a matching rule it forwards the segment to the proper system on the inside of the network
				if neither of the previus conditions are met, NAT/PAT device will throw it away
			most frontal assaults will be foiled by a NAT/PAT device
			the only packets that will be relayed from internet to systems on the protected side of the network are packets that meet a set of pre-written rules (stated before).
				this does not mean that your systems cant be hacked.
			computers that are infected with bots and rootkits can frequently bypass a firewall, 
				They frequently originate malicious traffic and most outbound communications are not filtered
			Another Layer of Defence:
				packet filters can scan and discard malicious packets based on a set of rules configured to allow or deny communications based on organization's policies

	Port Forwarding
		port forwarding is the application of rules that tell the NAT/PAT firwall which system on the internal network should handle a particular type of traffic.
			ex:	one possible rule might instruct a PAT device to forward all incoming TCP Port 80 requests to internal IP address 192.168.0.50.
				in this case there is presumably a server runing at IP 192.168.0.50 and this server has been configured to run as a web server.

			common practicce is for an end user/network administrator to deploy a strategy of using a host-based firwall.

Intrusion Detection Systems
	
	Intrusion Detection Systems (IDS) - designed to detect suspicious activity when it occurs once detected the IDS will:
		might simply log the event
		might actively notify the network admin.
	
	Network Based Intrusion Detection Systems
		IDSs are installed in one of two places:
			on each host
			on networking equipment that is able to see large portions of the network.
		Network-Based IDS is comprised of 2 different components:
			the system itself.
			its data collection probes (sensors).
				Network Probes:
					Responsible for reporting Pertinent network info back to the central IDS.
					Typically hardware devices that are placed in highly visible places through a network.
					put in places to observe most of the traffic traveling on a network.
					typically attacked at each switch so all network traffic of intrest can be observed.
	
	Network-Based IDS Deployment
		Network Based IDS's are deployed to:
			processing requirements of the IDS are frequently too much to be handled by the small probes attached to switches and routers.
			collecting and analizing all data in one place allows the IDS to examine simultaneous events occuring on different parts of the network.
		the IDS has a "birds-eye view of all the treaffic traveling in the network, allowing it to notice unusual activity.
			when a organization's servers starts sending data to an unknown system, the ids will be in position to observe and flag abnormal traffic.
	
	Protocol Analysis:
		initially Network-based IDS tracked only packets from point (a) to point (b). allowing admin to get a idea of data fowing in the networks.
			admin would need separate monitors and sniffers to examine data flows further.
				this approach offered no protection from hackers who embeded attacks inside of normal network traffic.
		ping - transmits a small packet of data to another system with the "echo" flag sent. if a system receives a ping packet it will sent the packet back to the sender. (unless admin disabled ping)
			well known and frequently used utility 
				enablig admin to determin wether or not a particular server is able to receive network traffic.
				used to see if workstating being repaired has network conectivity
		in 1997 - `98 TCP/IP had a defect in implementation of many major OS. 
			resulting in system crash whenever the system received a packet that was bigger than ~65000 bytes in size
			a hacker could create a packet bigger than the ~65000 byte limit and disguise it as an ordinary ping packet
			the hacker could send this packet to any victim and knew there was a good change if let through the defenses the system would be knocked offline.
			AKA Ping of Death
		Protocol Analysis
			represents a new form of intrusion detection
			IDS systems that are capable of Protocol Analysis have knowledge of how a protocol should work, capable of reconizing when something is amiss.
				ex. IDS with Protocol Analysis would examin incoming Ping of Death, notice its not properly formatted ping packet than take defensive action.
					all major OSs were fortified against Ping of Death.
	
	Application Layer Firewalls
		this type of firewall is capable of scanning data on the Network and Transport Layers (like a SPI firewall) along with the application layers.
			App layer firewall have knowlege of how common protocols like HTTP, STMP, etc... should behave and can spot unordinary behavior.
				
				ex1. SQL injection attack's goal is to overwrite part of a websight's configuration.
					if successful the victimized websight will begin redirecting its visitors to a hacker-ran websight
						that websight attempts to infect users with viruses, spyware, and trojans
					telltale sight of this SQL injection attack is extremely long page request transmitted to the web server being targeted.
				ex2. page requests are normally a few hundred characters in length; very long page requests might be several thousand charcters long.
					SQL injection attacks are over 4000 characters long
						page request of this length falls outside of the normal HTTP traffic for most web servers.
						
	Deep Packet Inspection (DPI)
		considerable disagreement within security industry on the precise meaning of "Deep Packet Inspection":
			a DPI implementation for some venders take the form of a partial proxy server
				buffering all of the TCP (or UDP) packets for an entire session and examining the application-layer transaction (Harrison).
			implementation from other vendors will inspect each TCP (or UDP) segment, analyzing only the content of that packet in relation to normal operation of that protocol.
			the reason for this disagreement about DPI is the controversy that surrounds the use of DPI to monitor internet use and behavior.
				advocates in favor of the freedoms allowed by the internet strongly discourage the use of DPI Technologies by ISPs
				Tech Evangelists encourage DPI to help keep the Internet protected from malicious behavior.
	
	Deep Packet Inspection Application
		The controversy that became a matter of public intrest is the European Commision case against the company called Phorm
			Phorm developed software that used DPI but to profile Internet Traffic for advertising and other purposes.
				the International Telecommunications Union (ITU) approved the latest requirements for DPI in working item Y.2779.
		recent malicious behaviour will undoubtedly encourage more tech groups to consider DPI as legitimate

		Ex. the most common methods of defeating an IDS by concealing malicious attacks inside IP fragments.
			when network receives IP packet thats too large, it fragments the packet into smaller fragments.
				these are reassembled when they are received by the destination 
				unless IDS is capable of reassembly and performing a close inspection on the traffic contained therein the attack pattern will remain unnoticed to the IDS
	NAT Environments
		address ranges used by NAT are defined by the Internet Engineering Task Force (IETF) in a Request for Comment (RFC) known as RFC1918 AKA Address Allocation for Private Internets.
			(www.ietf.org search for 1918, you can see all address ranges reserved)
		in a NAT environment, all computer workstations start off with internal IP addresses, packets are transmitted by each individual computer, complete with its source IP address and destination for the desired workstation.
			when packets reach the NAT Gateway/Proxy, the NAT device removes the computers internal IP address and substitutes it with an available public ip address.
				if not available IP address than the packet will get dropped or be redirected to some internal system.
	Deep Packet Inspection Application Scenarios
		ex. and attack has discovered a server that has not been patched against a recently disclosed buffer overflow vulnerability within a popular web server
			the vulnerability allows the attacker to execute code of their choice upon transmitting a HTTP "user agent" value of more than 50 characters AND a "query string" that is longer than 1500 bytes.
				because the total amount of data being transmitted is grater than 1450 byte limit for a single TCP segment
			the attacker's system and server are broken up into atleast 2 TCP segments

			EX 1
				IDS using a proxy-like deep packet inspection scheme buffers all packets associated with HTTP transaction.
					when all packets have been received the system examins the transaction, allowing it to discover the suspiciously long query in combination with the long user agent value
			EX 2
				IDS using a deep packet inspection that is lacking a proxy-like component might miss this attack.
					IDS examins each TCP setment and because long user agent string and extra- long query string are located in different segments, the attack will go unnoticed.
			IDS's with Proxy-like functionality enjoy increased security, they also represent a network bottleneck and may impact network performance.
	Host-Based IDS
		in a host based IDS, computers have software packages installed that examin the current state of the computers on which they are running:
			CPU Load, Network Traffic(incomming and outgoing), file integrity, log files, etc.
		anything running locally on the computer can be observed by a host-based IDS.

		EX. the different symptoms that might be exibited on a computer thats been compromised by a hacker or for of malware:
			Systems running slwly, Program crashes and other add behaviors
			unexpected events, like seldom-used program observed in the background.
			new processes running on the system.
	Centralized IDS monitoring
		IDS products are capable of reporting suspicious events to a central server. this way all suspicious activity in in one place and more meaning ful reports can be generated with this info.
		EX.
			most system admins would be intrested to learn that half of the systems on the network simultaneously begin exibiting the same strange behavior.
		Manufacturers that produce IDS systems, or organizations that offer centralized management offer these services:
			Network-Based IDS, Host-Based Software, and Centralized Monitoring
	Centralized IDS Monitoring Management
		all three work in concert to prevent and alert network administrators of intrusion attempts.
			a way to reduce the admin overhead required by an organization thats trying to manage a network-based IDS or several hundred computers all running a host-based IDS
				IDSs are frequently capable of running in a stand-alone manner.
	Intrusion Detection Strategies (IDS)
		hast-based and network-based use these detection strategies:
			Signature (Rule) Detection, Anomaly Detection, Heuristic Detection
	Signature (Rule) Detection - Signatures are profiles of some malicious activities (virus or worm, penetration attempt, etc.) that should be stopped.
		IDS is pre-configured with a large list of signatures. if the IDS observes network traffic that matches a signature it will respond in a preprogrammed way.
			must update definition files
				same with Anti-Virus Products, the signature files for a signature-based IDS need to be kept up-to-date in order to defend against the latest techniques used by hackers.
		Pros
			low false alarm rate, quick identification, vary accurate at detecting, based on known signatures.
		Cons
			False Negative Attacks	-	signature-based detection knows about attacks that it has been programmed to recognize.and new or unheard of attack will probably pass by a signature-based IDS.
			False Positive Attacks
				no two networks are configured equally, "normal" activity is diferent for every network. telltale sighns of an attack on one network might not be a attack on another.
				Most Signature-based IDS products come with a built-in database of common attack signatures. when first placed online it hasnt tuned to the organization's traffic, resulting in false positives.
					this same situation happens whenever a signature database is updated and new rules are added; some period of adkustment is frequently needed.
