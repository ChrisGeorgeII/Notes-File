Cloud Computing
  National Institute of Standards defines cloud computing as:
    a methodology for enabling convenient on-demand network access to a shared pool of configurable computing resources (networks, servers, and aplications) that can be rapidly provisioned and released with minimal management effort or service provider interactions. (NIST)
    allows people to access files, photos, songs, videos and host of other services on phones or laptops at any time. like a virtual infrastructure with its apps on a cloud-based network.

  Cloud-Based Networking - when some or all of an organization's networking resources are located in the cloud. 
    hosting networking resources in the cloud allows business to create complex networks using only internet connection.
      netwroking resources are normally hosted by a 3rd party cloud provider, 
      services that can be hosted by cloud networking:
        Network Management Software, Data Connectitivity, Virtual Routers, Firewalls, Load Balancers, Bandwidth, Content delivery network (CDN), Virtual Private Network (VPN), Domain Name System (DNS)

  Cloud Computing Services
    risks of cloud computing depend on the type of cloud computing model deployed. cloud computing can be clasified by types of offerings by tservice providers:
      Software as a Service (SaaS)        - refers to providing on-demand applications over the internet. (Ex. of SaaS providers: Salesforce Platform, Google Workspace, Hubspot, Zendesk, Freshdesk)
                                            one or more application and the computational resources to run them are provided as a turnkey service on demand. 
                                            all security provisions are carried out by the cloud provider.
                                            customer has no management or control over the underlying cloud infrastructure or applications.
                                            consumers can choose from preferred selections and usually limited admin application settings.
      Platform as a Service (PaaS)        - platform layer resources are provided that include operating system support and software development frameworks
                                            Ex. of Platform as a Service (PaaS) providers include: 
                                              Microsoft Azure, Salesforce Platform, Google App Engine, Amazon Web Services (AWS)
                                            This model of Service delivery reduces cost and complexity of housing, buying and managing underlying hardware and software components of the platform (programs or database Dev Tools)
      Infrastructure as a Service (IaaS)  - provides on-demand infrastructural resources such as computing power, storage, and networking
                                            IaaS platforms model of service delivery offers a platform for developing and executing applications, with resources virtualized and managed through a service interface.
                                            consumers can select OS, development environments, and configurations to meet their needs and implementing security measures beyond core infrastructure.
                                              Virtualized Infrastructure Layer Components: virtual machines, storage, network elements, and hypervisors
                                            Platform architecture supports: Compilers, Libraries, Middleware, Utilities, and software tools necessary for developing and deploying applications.

  Cloud Computing Summary
    Cloud Service Provider's Delivery model - defins what the network administrator (or customer) is responsible for.
    misunderstanding responsibilities of the customer and service provider causes unnecessary vulnerabilities due to improper maintenance of software.
      by carefully defining roles and responsibilities of a cloud service offering, a network admin can id the key areas of rsponsibility and focus their attention on securing those aspects.

  Authentication - the process of identifying a user or system as who or what they declare to be. ther are 2 types of Authentication:
    Private Network Authentication
      Private Network Authentication in a windows environment can occure through Active Directory or Local Authentication (NT LAN Manager, or NTLM)
      Active Directory:
        user credentials are validated via Local Security Authority Subsystem Service (Isass.exe), using kerberos protocol to comunicate with domain controller
      Kerberos:
        authenticates users without transmitting passwords in hash or cleartext form, reducing password cracking risks.
        supports single sign-on allowing users to access multiple systems with one logon "ticket"
        Local Authentication uses NTLM, lacking single sign-on, primarily maintained for backword compatibility.
        NTLM Vulnerabilities: Susceptibility to pass-the-hash attacks.
        use Kerberos along with contemporary authentication standards (OAuth 2.0, OpenID Connect, Multi-Factor Authentication (MFA)) to strengthen security.
    Cloud Atuthentication
      Public and hybrid cloud services (SaaS) leverage authentication method selected by the provider:
        database credential lookups, local directory access protocol (LDAP), or federated identity management.
        Federal Identity Management - a method of linking authentication credentials across identity management systems to enable single sign-on across multiple domains using open authentication standards.
          (The funcamentals of Identity Federation Techtarget) federated identity management involves the use of an identity provider (IP) and service providers (SP).
          Identity provider may be a service or server thats responsible for managing authentication requests
            if service provider is trusted: authentication metadata consisting of public key certificates, URL for single sign-on service, URL for the single sign-on Log off service, are provided.
            session tokens or cookies are used to enable single sign-on across federated applications or resources.

Virtualization
  Virtualization - allows multiple isolated operating systems or workloads to run on a single physical server by abstracting hardware resources into software-defined environments.
  
  virtualization tech can lead to substantial cost reductions for organizations transitioning from a non-virtualized IT infrastructure
    with potential total cost of ownership (TCO) savings ranging from 40% to 60% over a 3- to 5- year period.
      realized across multiple areas (hardware, energy consumption, and administrative overhead.
    evolution of virtualization to include containerization can offer even more profound efficiencies in specific use cases.

  Types of Virtualization:
    Application Virtualization  - Enables applications to run from a server without requiring file system, registry, or operating system changes on the device accessing the application.
                                  Enabling benefits: being able to run multiple versions of an application on a device, optimal use of hardware resources based on workload, and cost reduction in hardware and licensing.
    Operating System Virtualization - Enables running of several different Operating Systems in parallel on a single central processing unit (CPU)
    Network Virualization - enables the logical segmentation of phyzical network resources, enabling the resources to be pooled together.
                            Storage, processing, and applications may be shared across physical devices giveing flexibility of allocating resources as required.
    Server Virtualization - Enables running multiple servers that may have been running with low utilization rates onto fewer servers running at optimized server utilization rates.
                            decrease in numbers of servers results in a decrease in cost, energy, and hardware requirements.
                            VMWare states that server consolidation in a virtualized environment can reduce hardware requirements by 10:1 ratio. (VMWare)
    Storage Virtualization  - multiple physical network storage devices are combined to appear as one storage device that can be managed centrally.
                              storage virtualization reduces the complexity of performing common administration tasks (backups, restoration, and stroage allocation.)

  Virtualization Devices:
    Servers, Storage Area Networks, Routers, Business Applications.

  Virtualization Challenges
    60% of servers are running in virtualized environment and increasing. common virtualization challenges:
      Plan for Physical Device Failure
        consider hardware redundancy on hardware hosting virtual servers or devices.
        Ex.: hosting 5 servers on one. consider clustering the server or at minimum, insure physical host has redundant power supplies, network interface cards(NIC cards), and centalized network attached storage.
      New Administration Knowledge Required
        Managing a VMWare, Xen, or Hyper-V server is different than managing physical devices. admin staff should be trained prior to virtualization. Modify operations and disaster recovery procedures.
      Applications Consideration
        Not all applications will be supported to run in virtual evnironments. contact application providers prior to migrating.

Securing Cloud-Based Applications.
  
  Cloud Security
    securing cloud services requires collaboration between the cloud services provider and customer.
    security methods will depend on the type of cloud environment (Public, Private, or Hybrid and the cloud service being provided). 
      data being stored, transferred, or processed should be considered along with any compliance requirements
    Cloud Environements increas the risk of unauthorized access to confidential data due to the ability to access data from multiple customers through a single point of entry.
    Cloud security risks can be mitigated with a strong security policy and processes that were developed with an understanding of common security risks.
  
  Cloud Security Vulnerabilities:
    Insecure application and application programming interfaces (API), Abuse of cloud services, Shared Technology Issues, Dataloss or leakage, Account Authentication Breaches.
  
  Cloud Security Processes
    Cloud Security is a continuous process starting with the development of secure cloud platforms and applicaions.
    optimize and etect threats during operation (ensuring systems are patched and updated routinely, on cloud service provider and client sides).
      the following questions will assist in Identifying best security processes:
        what type of data is being managed in the cloud?
        what type of cloud model was selected (private, public or hybrid)?
        how will users authenticate to the cloud-based service?
        how will data be transmitted?

  Cloud Security Best Practices
    best practices that apply to in-house data centers apply to cloud service consumers and providers 
      data may be physically located at any location in a public cloud environment.
      multiple customers may be sharing common resources.
      sensitive data may be transferred and stored outside of private networks.
      Firewalls:
        designed to prevent unauthorized access to or from a network. rules are established to implement security policies to grand, deny, and log network actigity based on admin criteria.
        cloud-based firewall - optimized for private and public cloud environments enabling consistency across physical, virtual, and cloud environments.
        firewalls designed for cloud providers enable multi-tenancy security configuration capabilities.
      Data Encryption
        encryption is the science of storing info in a way that allows it to be revealed to those that want access to it.
          Data is made unreadable until it is unlocked by using key algorithm.
          data should be encrypted prior to being transferred or stored in public and private clouds.
          encryption secures data regardless of physical location.
             important in a cloud environment where physical location of data meay be unknown. (Encryption, Not Restriction: Nextgov)
          encrypting data prior to transfering to cloud ensures only customer can decrypt or unlock data. 
          Encryption services can provided by vendor wher vendor has promised confidentiality regarding data contents.
      Anti-Virus
        cloud consumer and provider should ensure they have implemented anti-0virus, malware, and anti-spyware tools that are regularly updated.
        customers need to work with cloud service providers to configure anti-virus exclusion rules for trusted files being transferred across the internet to customer devices.
          sometime anti-virus software will quartine these files if rules are not established properly.
      Data Loss Prevention (DLP)
        Data Loss Prevention Software can be used to ensure that confidential informaiton is tracked and transfer is controlled. 
        Data is tagged based on a set of business rules that establish constrains for data in transit and at rest (stroage).
      Securing Application Vulnerabilities  
        Customer Leveraging Software As a Service (SaaS) should verify that providers have done their due diligence when developing applicaiton
          Including trace analysis for security vulnerabilities during code development. customer should understand contractual obligation of providers maintaining the app against new discoverd threats.
      Security Authentication
        authentication to cloud services should be accomplished using authentication protocols and customer methods for auditing access to systems, data and processes.
        public cloud access can be controlled using federated identity management when offered to enable single sign-on and security of authentication methods once available on private networks.

  Cloud Analysis: Regulation Requirements
    when considering cloud solutions evaluate how well the service provider align with key regulatory requirements: 
      Sarbanes Oxley, Payment Card Industry Data Security Standard (PCI DSS), Health Insurance Portability and accountability act (HIPAA)
    laws and standards ensure data is handled securely, responsibly and in compliance with industry rules.

  Complying with Regulations
    providers use multilayered security practes to protect customers' data:
      Facilities: 
        Double wall construction, Biometric and video surveillance security, on-site securtiy guards, raised floors and seismically protected equipment, dry-pipe fire protection tech, for damage control(earthquakes, flooding, fire, and natural disasters), visitors escorted, dual redundant power supplies
      Data Transmission
        senders must upload files to servers in datacenters, an email is automatically generated to the recipients wwho can download the file:
          Secure Socket Layer (SSL) protocol is used to protect data integrity during file transfer (for online payments and user registration)
          industry-standard 128-bit SSL encryption deployed using Class 3 certificates and server-gated cryptography (SGC)
          authentic delivery is used requiring a file recipient to be registered with an account, they must login with username and password before allowed to download files.
      Payment Card Industry Data Security Standard
        PCI DSS 4.0 introduces requirements that impact how organizations handle and protect paymet card data, making compliance more complex and critical.
          PCI is not a federal regulation, adherence is mandatory for any business that processes credit card transactions and failure to copmly can result in financial and reputational concequences.
            providers implement multilayered security strategies, combining technical controls, policies, and monitoring practices to safeguard customer data.
      Network Access Control
        Network and ISP grade firewalls providing IP filtering and intrusion detection protection.
        servers are constantly upgraded with leading firewall products
        regular vulnerability scans of internal networks are conducted to practively detect and prevent security threats.
      Credentials
        users register via valid email address and strong password
        credentials are encrypted during transmission and storeage via one-way hash.
        password requests are verified by requiring the user to validate their email address prior to password reset.
      Data Retention
        uploade files are managed and retained in accordance with organization and site-specific data retention requirements, constistent with applicable laws, regulations, and operational needs.
          in alignment with NIST SP 800-53, control SI 12 (Information Management and Retention), info is "managed and retained ... in accordance with applicable laws, executive orders, directives, regulations, policies, standards, guidelines, and operational requirements"
            retention periods are determined based on data classification and records management policies, and data is retained only for as long as it is required to support administrative, legal, audit, or operational purposes, consistent with NIST SP 800-53, control AU-11 (Audit Record Retention)
              upon reaching the end of its approved retention period, data is securely disposed of in accordance with established deletion and sanitization procedures.
                to support system availability and resilience, server redundancy is implemented so data may be replicated accross multiple systems to mitigate the impact of server failures.
      Data Storage
        stored files are encoded and scrambled to make it impossible for a network intruder to identifyh a file by its original name or to read its content.
        file download require authentication of a user's complete credentials.
      Auditing
        Tracking tools are provided to customers enabling them to monitor the number of times a file has been downloaded, the time downloaded, and who downloaded it.
        Audit trails enable customers assurance that cloud service provider is in compliance with government regulations regarding the traceability of information privacy and accidential disclosures
        PCI compliance is necessary to require with the privacy provisions of the Gramm-Leach-Biley (GLB) Act which is the governing agency that regulates the activities of the financial services indurstry.

  Vulnerabilities
    cloud providers layer security across many levels, leaving a number of issues and vulnerabilities that must be considered before deciding to deploy to a cloud environment:
      Access Control:
        does the cloud service provider use recent, state-of-the-art access controls and encryption technologies? 
          how often do they update?
      Insider Threats:
        what policies does the cloud provider have in place to deal with insider threats? 
          Accidental Disclosures? 
            Who is responsible and legally liable if your data get released?
      Service Availability:
        what is the service availability offered by provider? 
          will you be able to access data when you need it? 
            what are hurdles you may face if obtaining data in the event of an earthquake, fire, hurricane, flood, or other natural disasters?
      Required Regulations:
        what regulatory requirements are you required to have in place if yor store data at your business? 
          does your cloud provider offer you the same requirements?
      Auditing Services:
        Does the service provider use imdependent auditing services? 
          If so who? 
            Will they provide outside refrence information so you can obtain information from their auditors about their security and policy practices?
      Data protection Policies:
        what policies does the cloud service provider use to protect your data? 
          Are these policies clearly written out and provieded to you in a service agreement? 
            is this agreement non-negotiable or do you have some room for negotiation to ensure your particular situational needs will be covered?
      Vulnerability Scanning:
        what type of security and vulnerability canning does the provider have in place?
          how often are security threat issues addressed in a 24-hour period?
            what are their proactive security policies and practices in order to prevent data breaches?
      Incident Response Policies:
        what policies does the cloud provider havce in place for incident reporting, handling and response in case of security breach?
          will you be notified?
            do any federal regulations require that the provider notify you for information is lost, stolen, or disseminated?
      Risk Management Policies
        what type of risk management policies does the cloud provider have in place?
          if there is a breach or loss of data, what is their policy for covering your losses
      Personnel
        what level of skilled personnel are hired by the provider?
          are they specialized IT personnel or do they mostly hire recent graduates?
      System Configuration
        what type of patch management and system configuration does the cloud service provider use?
          be sure to get written copies of policies and any legal terms of agreement you have to agree to in order to use their services.
      backup and Recovery
        what type of backup and recovery systems does the provider use?
          what type of redundancy systems are in place?
      Certifications
        does the cloud provider have any accreditations or certifications like BBB or security Certifications?
          if the provider does not have any of these, why not?
