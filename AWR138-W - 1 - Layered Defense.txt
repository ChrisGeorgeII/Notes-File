Firewalls
  firewall  - a device that is designed to prevent unwanted, potentially malicious network traffic from reaching a particular computer or computer network.
  statful packet  - a small amount of data sent over a network or networks
  To prevent hackers and malware from gaining direct access to computers on a network.
  SYN-ACK
    SYN - Synchronize
    ACK - acknowledgment
  3 way handshake:
    client to server: sends packet with syn
    Server to Client: sends back SYN and ACK
    client to server: sends packet to server, sets ACK
  SPI firewalls 
    uses Stateful Packet Inspection (SPI) to track every incoming and outgoing packet for authenticity
    the advantage of using stateful packet inspection firewall is it tracks each connection's current status which blocks invalid packets from reaching intended target.
      to determin if a packet is legimimate:
        the only way the packet could be legimate is if the intended recipient of this SYN-ACK packet sent the remote system a SYN packet beforehand.
        local system send a SYN packet to the remote address at some time in the recent past

  NAT and PAT firewalls
    Network address Translation (NAT)
      combines NAT component and traditional SPI firewall
      keeps track of a pool of IPv4 address and associats a public address with each system as it request access to the internet
        when attempting to transmit data to internet, Nat performs a "translation" inserting the public address associated with that host iunto the IP header.
    Port Address Translation (PAT)
      allows multiple computers to utilize the internet simultaneously using a single public IP address
  limitations and complications of network addresses
    IP address  - four sets of 3 digits each separated by periods, each set of 3 digits is called an octet, each octet range from 0 to 255
      beginning with 0.0.0.0 through 255.255.255.255
      provides 4.3 billion routable address
    # of IP address
      each octet is 8 bits in length (00000000.00000000.00000000.00000000)
      total number of address equaling 232 or 4,294,967,296
    IP address allocation
      ip addresses are allocated/assigned in blocks reffered to Class A, Class B, and Class C
      each block of address in a givven class consist of consecutive addresses totaling:
        Class A = 16,777,216 addresses
        Class B = 4,048,576
        Class C = 65,536
    # of Public IP addressesconnected devices
      588,514,304 addresses are reserved for administrative purposes.
        out of 4,294,967,296 addresses that leaves 3,706,452,992 routable or public addresses.
    connected devices
      14.2 billion devices connected to the internet in 2019, prjected that in 2021 there will be 25 billion devices conneted.
        these devices, aka "things," comprise what is being referred to as "The Internet of Things (IOT)
    IANA  - (Internet Assigned Numbers Authority)
      department of ICANN (nonprofit private American corporation)
      responsible for global coordination of the Internet Protocol addressing systems
        includes Autonomous System Numbers used for routing internet traffic
    IPv4  - 32-bit numbers, often expressed as 4 cotets in "dotted decimal" notation
      IPv4 has 4.3 billion routable addresses
    IPv6  - 128-bit numbers conventionally expressed using hexadecimal strings
      IPv6 accommodates over 340 undecillion unique addresses (340 followed by 36 zeroes)

  TCP/IP and PAT
    TCP
      IP identifies each system in a connection by associating the hardware [MAC] address with an IP address
        TCP identifies applications on these systems that are communicating by usilizing ports.
      remote
        on the private side of a PAT device when a device wants to connect to a remote system, the device constructs an ordinarry TCP segment, contained in an IP packet
          the TCP header contains both destinations and source port numbers
            for most communications the destination port number will be a port number (80 for HTTP, 25 for SMTP, etc...) when source port number will be a random number grater than 1024
              similar to port remapping it involves changing the port number used for certin types of communications on a system
                when remapping, a PAT device can hide the real port number of an internal application from the outside world.
        PAT device can Uniquely Identify every connection running on a network.
      headers
        on the private side of a PAT device, the Pat takes the TCP segment and changes the headers.
        Source IP address is changed from private IP address that the host submitted, to global IP address being shared by the PAT device.
        Source TCP port may be changed depending on the implementation on whether or not another PAT decided to use that TCP port.
      segment
        "after changing these items" the PAT sends the segment to its original destination
          Neither the server nor the host on the private side of the PAT firewall knows that the PAT is in use.
          is possible to tell when host is using a PAT device, "look for clues"
      response
        When Server sends data back to client, PAT device receives, looks at what server sent the segment, what destination port, forward the segemnt to proper host
          similar to how internal port number is hidden, a PAT device hides internal hosts from outside attackers using the private addresses.
      TCP
        Majority of the Network Traffic found on the internet utilizes Transmission Control Protocol (TCP) over the Internet Protocol.
          PAT takes advantate of these protocols allowing multiple computers to use the same Public IP Address
        all systems on the private side of a PAT device have private IP addresses
        NAT and PAT are highly similar
  Security of NAT/PAT firewalls
    Nat and PAT firewalls offer some defence over traditional firewalls
      NAT/PAT device receives a TCP segments for a Public IP address on a network, examins the segment and carrys out one of the following:
        if segmentis part of a known ongoing TCP connection, forward segment to proper system on the inside of the network
        if segment is a new connection request, looks at its forwording table; if it finds a matching rule it forwards the segment to the proper system on the inside of the network
        if neither of the previus conditions are met, NAT/PAT device will throw it away
      most frontal assaults will be foiled by a NAT/PAT device
      the only packets that will be relayed from internet to systems on the protected side of the network are packets that meet a set of pre-written rules (stated before).
        this does not mean that your systems cant be hacked.
      computers that are infected with bots and rootkits can frequently bypass a firewall, 
        They frequently originate malicious traffic and most outbound communications are not filtered
      Another Layer of Defence:
        packet filters can scan and discard malicious packets based on a set of rules configured to allow or deny communications based on organization's policies

Intrusion Detection Systems
  Intrusion Detection Systems (IDS) - designed to detect suspicious activity when it occurs once detected the IDS will:
    might simply log the event
    might actively notify the network admin.
  
  Network Based Intrusion Detection Systems
    IDSs are installed in one of two places:
      on each host
      on networking equipment that is able to see large portions of the network.
    Network-Based IDS is comprised of 2 different components:
      the system itself.
      its data collection probes (sensors).
        Network Probes:
          Responsible for reporting Pertinent network info back to the central IDS.
          Typically hardware devices that are placed in highly visible places through a network.
          put in places to observe most of the traffic traveling on a network.
          typically attacked at each switch so all network traffic of intrest can be observed.
  
  Network-Based IDS Deployment
    Network Based IDS's are deployed to:
      processing requirements of the IDS are frequently too much to be handled by the small probes attached to switches and routers.
      collecting and analizing all data in one place allows the IDS to examine simultaneous events occuring on different parts of the network.
    the IDS has a "birds-eye view of all the treaffic traveling in the network, allowing it to notice unusual activity.
      when a organization's servers starts sending data to an unknown system, the ids will be in position to observe and flag abnormal traffic.
  
  Protocol Analysis:
    initially Network-based IDS tracked only packets from point (a) to point (b). allowing admin to get a idea of data fowing in the networks.
      admin would need separate monitors and sniffers to examine data flows further.
        this approach offered no protection from hackers who embeded attacks inside of normal network traffic.
    ping - transmits a small packet of data to another system with the "echo" flag sent. if a system receives a ping packet it will sent the packet back to the sender. (unless admin disabled ping)
      well known and frequently used utility 
        enablig admin to determin wether or not a particular server is able to receive network traffic.
        used to see if workstating being repaired has network conectivity
    in 1997 - `98 TCP/IP had a defect in implementation of many major OS. 
      resulting in system crash whenever the system received a packet that was bigger than ~65000 bytes in size
      a hacker could create a packet bigger than the ~65000 byte limit and disguise it as an ordinary ping packet
      the hacker could send this packet to any victim and knew there was a good change if let through the defenses the system would be knocked offline.
      AKA Ping of Death
    Protocol Analysis
      represents a new form of intrusion detection
      IDS systems that are capable of Protocol Analysis have knowledge of how a protocol should work, capable of reconizing when something is amiss.
        ex  - IDS with Protocol Analysis would examin incoming Ping of Death, notice its not properly formatted ping packet than take defensive action.
          all major OSs were fortified against Ping of Death.
  
  Application Layer Firewalls
    this type of firewall is capable of scanning data on the Network and Transport Layers (like a SPI firewall) along with the application layers.
      App layer firewall have knowlege of how common protocols like HTTP, STMP, etc... should behave and can spot unordinary behavior.
      It watches application layer traffic like HTTP and SMTP for signs of abnormal activity, which could mean an attack is underway.
        
        ex1 - SQL injection attack's goal is to overwrite part of a websight's configuration.
          if successful the victimized websight will begin redirecting its visitors to a hacker-ran websight
            that websight attempts to infect users with viruses, spyware, and trojans
          telltale sight of this SQL injection attack is extremely long page request transmitted to the web server being targeted.
        ex2 - page requests are normally a few hundred characters in length; very long page requests might be several thousand charcters long.
          SQL injection attacks are over 4000 characters long
            page request of this length falls outside of the normal HTTP traffic for most web servers.
  
  Deep Packet Inspection (DPI)
    considerable disagreement within security industry on the precise meaning of "Deep Packet Inspection":
      a DPI implementation for some venders take the form of a partial proxy server
        buffering all of the TCP (or UDP) packets for an entire session and examining the application-layer transaction (Harrison).
      implementation from other vendors will inspect each TCP (or UDP) segment, analyzing only the content of that packet in relation to normal operation of that protocol.
      the reason for this disagreement about DPI is the controversy that surrounds the use of DPI to monitor internet use and behavior.
        advocates in favor of the freedoms allowed by the internet strongly discourage the use of DPI Technologies by ISPs
        Tech Evangelists encourage DPI to help keep the Internet protected from malicious behavior.
  
  Deep Packet Inspection Application
    The controversy that became a matter of public intrest is the European Commision case against the company called Phorm
      Phorm developed software that used DPI but to profile Internet Traffic for advertising and other purposes.
        the International Telecommunications Union (ITU) approved the latest requirements for DPI in working item Y.2779.
    recent malicious behaviour will undoubtedly encourage more tech groups to consider DPI as legitimate
    Ex. - the most common methods of defeating an IDS by concealing malicious attacks inside IP fragments.
      when network receives IP packet thats too large, it fragments the packet into smaller fragments.
        these are reassembled when they are received by the destination 
        unless IDS is capable of reassembly and performing a close inspection on the traffic contained therein the attack pattern will remain unnoticed to the IDS
  
  NAT Environments
    address ranges used by NAT are defined by the Internet Engineering Task Force (IETF) in a Request for Comment (RFC) known as RFC1918 AKA Address Allocation for Private Internets.
      (www.ietf.org search for 1918, you can see all address ranges reserved)
    in a NAT environment, all computer workstations start off with internal IP addresses, packets are transmitted by each individual computer, complete with its source IP address and destination for the desired workstation.
      when packets reach the NAT Gateway/Proxy, the NAT device removes the computers internal IP address and substitutes it with an available public ip address.
        if not available IP address than the packet will get dropped or be redirected to some internal system.
  
  Deep Packet Inspection Application Scenarios
    EX. and attack has discovered a server that has not been patched against a recently disclosed buffer overflow vulnerability within a popular web server
      the vulnerability allows the attacker to execute code of their choice upon transmitting a HTTP "user agent" value of more than 50 characters AND a "query string" that is longer than 1500 bytes.
        because the total amount of data being transmitted is grater than 1450 byte limit for a single TCP segment
      the attacker's system and server are broken up into atleast 2 TCP segments
      EX 1  - IDS using a proxy-like deep packet inspection scheme buffers all packets associated with HTTP transaction.
              when all packets have been received the system examins the transaction, allowing it to discover the suspiciously long query in combination with the long user agent value
      EX 2  - IDS using a deep packet inspection that is lacking a proxy-like component might miss this attack.
              IDS examins each TCP setment and because long user agent string and extra- long query string are located in different segments, the attack will go unnoticed.
      IDS's with Proxy-like functionality enjoy increased security, they also represent a network bottleneck and may impact network performance.
  
  Host-Based Intrusion Detection System(IDS) - a security software installed directly on an individual endpoint (server, workstation, virtual machine) to monitor internal operating system activity, file modifications, system calls, and log files for signs of malicious behavior
    in a host based IDS, computers have software packages installed that examin the current state of the computers on which they are running:
      CPU Load, Network Traffic(incomming and outgoing), file integrity, log files, etc.
    anything running locally on the computer can be observed by a host-based IDS.
    EX. - the different symptoms that might be exibited on a computer thats been compromised by a hacker or for of malware:
        Systems running slwly, Program crashes and other add behaviors
      unexpected events, like seldom-used program observed in the background.
      new processes running on the system.
  
  Centralized IDS monitoring
    IDS products are capable of reporting suspicious events to a central server. this way all suspicious activity in in one place and more meaning ful reports can be generated with this info.
    EX. - most system admins would be intrested to learn that half of the systems on the network simultaneously begin exibiting the same strange behavior.
    Manufacturers that produce IDS systems, or organizations that offer centralized management offer these services:
      Network-Based IDS, Host-Based Software, and Centralized Monitoring
  
  Centralized IDS Monitoring Management
    all three work in concert to prevent and alert network administrators of intrusion attempts.
      a way to reduce the admin overhead required by an organization thats trying to manage a network-based IDS or several hundred computers all running a host-based IDS
        IDSs are frequently capable of running in a stand-alone manner.
  
  Intrusion Detection Strategies (IDS)
    hast-based and network-based use these detection strategies:
      Signature (Rule) Detection, Anomaly Detection, Heuristic Detection
  
  Signature (Rule) Detection - Signatures are profiles of some malicious activities (virus or worm, penetration attempt, etc.) that should be stopped.
    IDS is pre-configured with a large list of signatures. if the IDS observes network traffic that matches a signature it will respond in a preprogrammed way.
      must update definition files
        same with Anti-Virus Products, the signature files for a signature-based IDS need to be kept up-to-date in order to defend against the latest techniques used by hackers.
    Pros
      low false alarm rate, quick identification, vary accurate at detecting, based on known signatures.
    Cons
      False Negative Attacks  - signature-based detection knows about attacks that it has been programmed to recognize.and new or unheard of attack will probably pass by a signature-based IDS.
      False Positive Attacks
        no two networks are configured equally, "normal" activity is diferent for every network. telltale sighns of an attack on one network might not be a attack on another.
        Most Signature-based IDS products come with a built-in database of common attack signatures. when first placed online it hasnt tuned to the organization's traffic, resulting in false positives.
          this same situation happens whenever a signature database is updated and new rules are added; some period of adkustment is frequently needed.
  
  Anomaly Detection - monitoring strategy used by Intrusion Prevention or Intrusion Detection systems to id potential attacks by comparing a system's current activity
    designed to solve a problem with signature-based detection's inability to recognized new, previously unseen attacks.
    it establishes a baselin then considers anything outside that normal activity to be suspicious activity.
    Changes EX.     - Web server receives incoming network traffic on TCP ports 80 and 443 and might talk to a database server and send log reports to central log server.
                      if webserver sends network traffic out on TCP port 25, this is a change in behavior. webserver has been compromised.
    Detection EX.   - Anomaly detection frequently uses some form of AI, its able to precisely learn the patterns that make up normal behavior for computer/network.
                      training period is still required while the IDS learns about its environment.
                      admin will be required to provide the system with constant feedback regarding things that are normal and abnormal.
    Challenges EX.  - Anomaly Detection Suffers from the following inverted set of problems:
                      Low false negative error rates, high false positive error rates. particularly while training the system.
                      after the system has been deployed, high false positive error rates may still be observed.
    Advantages EX.  - Anomaly detection offers several advantages in comparison to Signature-Based Detection.
                      no signature files to update
                      earlier detection of new types of attack
                      Anomaly detection bases its decisions on previously observed behavior and capable of discovering new types of attack that may be missed by a signature-based detector.
  
  Heuristic Detection - operates by comparing incoming traffic and packets to Pre-Established baseline of normally experienced behavior for a specific network.
    Hybrid Methodology  - science behind creating and id the profiles of a given network differ widely.
      merges the signature-based methodology with an anomaly discovering engine.
        Methods of Profile-based Detection:
          Artifical Nural Network EX. - means of doing machine learning, in which a computer learns to perform some tasks by analyzing training examples.
                                      A term used to describe a type of methodology that will use a small profile data set to classify intrusions
                                      Nural netowrk trained against profile data set by an algorithm that looks for patterns that are contrary to the pattern matching that it was able to perform with the profile.
                                      uses artificial network to determine what types of behavior are considered normal.
          Fuzzy Logic EX.             - Scientists have begun to research how IDS systems can perform the same type of logic when analyzing traffic patterns.
                                       by using probabilistic or multi_valued logic, the IDSs can make a "fuzzy" guess that has found an anomaly rahter than an exact pattern match.
  
  Choosing an IDS
    most IDS's utilize Signatiure-Based Detection.
    as general rule is anomaly-based detection is used more frequently in host-based IDS's rather than Network-Based IDS's.
    Anomaly-based detection may be offered as a supplemental technology, designed to complement signature-based detection rahter than replace it.
    new profile-based detection methods have begun to make their way into IDS technology
      Heat Index, or the ability to control how aggressive the IDSis based on how close the pattern recognition is to what is considered the acceptable profile of organization.

Intrusion Prevention Systems (IPS) - device designed to monitor a particular netowrk or computer for signs of an attack happening, once spotted the system takes action to prevent the attack from spreading
  when a possible attack is spotted the system notifies an admin and take whatever steps it can to block the intrusion(attack) from progressing.
  
  IDS and IPS are alike in many ways
    IPS can be divided into:
      host-based: runs on each individual computer
      Network-Based: run on a centralized server
    where IDS was a step forwared in security tech but some felt that Intrusion Detection Systems could do more and created Intrusion Prevention Systems
      IPS Action Options
        similar to IDSs the the ability to intervine with a problem occurs
          EX.   - when a false positive error is reported by an ISP, it will do one of the following:
                    cut off network access to some portion of the network.
                    lock down a workstation.
                    block incoming connections to a critical server.
                    reset a specific TCP session.
      IPS Detection 
        care must be taken when configuring and deploying IPSs
        IPS uses two different types of detection: Signature and Anomaly with their own strengths and weaknesses
        Anomaly - is any change in behavior from ordinary, expected behavior. anomalies usually indicate an attack of some form is taking place.
  
  Network-Based Intrusion Prevention Systems - an inline security hardware or software tool that continuously monitors network traffic to detect and automatically block malicious activity in real time
    protect large portions of computer network, if not the whole network.
    in general difference in IPS and other security appliances (IDS) is the response.
    IPS are configured to have the ability to in some way stop the suspicious activity.
      EX. halt all network traffic from the web server until the network administrator can sort things out.
  
  Host-Based Intrusion Prevention Systems - software security tool installed on a single endpoint (server, laptop, or virtual machine) that actively monitors, detects, and blocks malicious activity from within that device.
    Host-Based IPSs monitor and defend a single computer (host)
      uses components of the local system to monitor for intrusions (file integrity checking, log file monitoring, etc...)
        ISPs also must monitor the applications and programs running on the system in order to defend against potential intrusions.
        IPS can embed itself into Microsoft Windows, when macro virus prompts word to delete all files on HD, instructions get inspected by IPS, IPS decides if harmful it does not relay them to the OS.
  
  IPS detection Methods
    IPS and IDSs use both signature (rule) detection and anomaly detection. similar trade offs for each approch in an ips and ids are similar
      Signature vs. Anomaly Detection in IPS
        most IPS's use signature-based detection, but as a general rule, anomaly-based detection is used more frequently in host-based IPSs rather than network-based IPSs- though can be find in either type of IPS
        Anomaly-based Detection can be offered as a supplemental Technology designed to complement signature-based detection rather than replace it.
    Manageing IPS False Positives
      EX. - IPS might cut off network acces to a computer or group of computers inccorrectly, imparing those systems usability.

Cryptography
  Encryption - the process of converting data from its original form into some encoded format that cannot be read or understood without first decrypting it using the proper key.
  
  Applications of Cryptography
    EX. unless organization owns all transmission lines used to cary data from point to point, you wont beable to guarantee that data might be viewed by someone unknown or untrusted. the proper responses are:
        do not transmit data electronically
        use encryption to secure the data.
  
  Components of Cryptography: Cipher
    cipher is an algorithm used to encrypt data, both parties must agree upon a cipher in order for successful transmission to occur.
      EX. - like how someone speaking a different language to prevent eavesdropping. both must agree to speak the language. if one speeks a different language it wont work.
  
  VPN Uses
    Provider-Provisioned VPNs are not as common as user-provisioned VPN. (this course will focus on user-provisioned VPNs)
      VPNs are frequently used in 2 ways:
        a way of connecting individual computers to the corporate network
        a way of bridging the networks from two separate corporate locations 
  
  Components of Cryptography
    key - secret piece of data that enables cleartext to be encrypted into ciphertext, allows siphertext to be decrypted back into cleartext. ensuring those who know the key can access original information.
      EX. - 2 people dont know any other languages, might use code words or words that have special meaning.
            the code words and their actualmeanings would be an example of a key.
    Cleartext - the original "unscrambled" data that has yet to be encrypted or has already been decrypted. 
      AKA - The data that NEEDS to be protected or encoded to prevent unauthorized acces during transmission or storage
      cleartext Ex.   - when user types password, sends email, or enters credit card info into a websight, the info exists as clear text at some point in the process.
      Block Cipher    - a cipher that divides the cleartext into equal size chunks then encrypts each chunk separately. with input and key the output will always be consistant and not affected by time.
      Stream Cipher   - a cipher that encrypts cleartext one character (byte) at a time.
                          a stream cipher only uses a portion of the key stream to encrypt a byte teh cipheertext produced by the cipher may vary from moment to moment.
                          EX. - the ciphertext produced by encrypting the letter "A" at different time will appear different because of tperforming encryption with a different part of the key stream.
    Ciphertext  - the output of cipher, or encryption algorithm, and refers to data that has passed through an encryption process.
                    the scrambled data produced by the encryption function, when encrypted it cannot be easily converted back into the original data without the key.
                EX. - the message "Meet me at 5 PM" using an encrytpion algorithm and secret key, it might look like "6fA3$kL!2xQ" and cant ealisy be converted back without the correct cipher key.
  
  Encryption Key Security
    if an attacker can get acces to the private key used to encrypt data, then the situation is lost.
    some attackers might not attack the system from the internet, sometime its from the inside.
    Encryption Key Security Recommendations
      keep in mind when securing cryptographic keys:
        restrict access to the keys to only the personnel who truly need acces to them.
        physically secure the keys, perhaps on removeable data that is itself kept under lock and key. 
          when physically securing a key to removable data, remember people are not the only adversary. should also protect the key from fire and water
        dont store the keys with the data that is being protected. evin if the attacker gains access to one or the other thay still wont have acces to the data.
        encrypt the encryption key itself using a passphrase or some other item that can be easily remembered
  
  Cryptography Standards
    recommended that you select one published and certified cryptographic standards
      International standards occasionally found to have design defects, the design defects can often leave protected data vulnerable to decryption by someone other than the intended recipient.
  
  Symmetric Key Cipher  - an encryption method in which only one key is used between two parties
    because knowledge of this key make decryption possible, the shared key must be securely exchanged between the parties and is often a challenge.
    easy to use for personal data use, only requires one key and is fast and light on resource usage.
    brute force and dictionary attacks are often successful in breaking symmetric keys.
  
  Asymmetric Key Cipher - encryption method in which two or more keys are used, such as one key for encryption and another for decryption.
    each person uses a pair of keys:
      Public Key    - can be shared openly, allowing other to encrypt messages intended for the key owner
      Private Key   - only the matching private key can decrypt those messages.
    Ideal for secure communication over untrusted networks.

      Commonly encountered protocols:
        DataLink Layer (L2)
          encryption products available at Data Layer (L2) are designed to be used on wireless devices.
            large organizations needed to deploy wireless networks with the same level of security as offered by wired counterparts.
            because wireless networks use radio waves to transmit data, there is little control over who is able to see the data being transmitted.
            most wireless encryption offerings only attempt to keep data secret from outsiders
            most technologies are designed in such a way that there is little defense against insider threats.
          WPA/WPA2
            The primary encryption difference is that WPA uses the Temporal Key Integrity Protocol (TKIP) based on the RC4 stream cipher, 
              while WPA2 uses the much stronger Advanced Encryption Standard (AES) via the Counter-Mode/CBC-MAC Protocol (CCMP)
            older wireless encryption protocols (WEP - Wired Equivalent Privacy) are considered obsolete and insecure.
              Vulnerabilities that allow attacker to crack its encryption.
            WPA2 uses advanced encryption standard (AES) a robust and widely trusted encryption algorithm
            Always use WPA2 (or WPA3 where available) for wireless security and dont use WEP or WPA, they nolonger meet modern security requirements.
          Wired Networks
            traffic transmitted over wired network can be seen by evesdroppers, anyone with physical access to a wired network can listen to all of the traffic being transmitted on their segment of the network

        Network Layer Encryption
          Internet Engineering Task Force (IETF) hublised standard 4301, introducing the IPsec protocol to provide secure communications at the network layer of the TCP/IP stack
            IPsec is built into most all networking appliances taht are sold, also has been added to the definition of the IPv6 Protocol.
              Ipsec Provides the following assurances:
                data was not modified in transport
                senders are who they claim to be
                data was not read while in transport
              IPsec operates in two different modes:
                Transport Mode  - IPsec provides encryption at the network layer by encrypting only the payload of the IP packet while leaving original IP header exposed.
                  protecting the data from being read by attackers but reveals metadata such as source and destination IP address
                    an observer can see who is communicating but cant access the contents of the message.
                  Transport mode is commonly used for End-to-End communication between two hosts that both support IPsec, such as client and server.
                    ensures data confidentiality and integrity, but dusnt conceal the id of the endpoints or traffic patterns.
                  site to site VPNs prefer Tunnel Mode because it encrypts the entire original IP packet including the header.
                Tunnel Mode:
                  the original IP packet is encrypted, including the IP header.
                  the encrypted packet is placed inside of another packet, the outer packet is not encrypted
                    routers on the internet will have an IP header that can be read and used to route the packet to its destination
                  IPsec Designers claim that sender and receiver of packets transmitted in tunnel mode are completely hidden.
                    IP addresses of the gateway routers for sending and receiving networks are still in view.
                      possible to determin which networks exchanged the packets.
                Authentication Header Protocol (AH):
                  Authentication Header (AH) designed to ensure both the integrity and authenticity of IP packets during transmission.
                    verifies packet has not been altered or corrupted and confirms that it was sent by the system identified in the IP header:
                      AH appends a header to the IP packet data required for integrity checks and authentication.
                      before sending, sender calculates a hash value of the packet using SHA01 algorithm and includes it in the AH header
                      when received, the receiver recalculates the hash and compares it to the value in the AH.
                        if the 2 match the packet is confirmed to be intact and unmodified.
                      AH uses Security Association to validate identity
                        an exchange of information between both parties to confirm who they are
                        security associations include cryptographic credentials like digital certificates or public keys enabling AH protocol to verify each participant's ID.
                Encapsulating Security Payload (ESP) Protocol - Ensure Confidentiality of the data that is being transmitted.
                  the other protocol used by IPsec
                  ESP encrypts the payload of an IP packet using secure cipher(AES or Triple DES)
                    Ex. Tunnelmode is used to hide ip address of sender and receiver, transport mode only hides the info that is being transmitted. (someone who evesdrops on packets sent in transport mode will see correct IP address of sender and receiver.
                Encapsulating Security Payload Protocol Transport Mode:
                  1. regular IP packet is generated
                  2. before being transmitted the payload of the packet is encrypted.
                  3. the packet with its encrypted payload is transmitted. ip header remains unchanged (i.e., it isnt encrypted)
                Encapsulating Security Payload Protocol: Tunnel Mode
                  1.  regular IP packet is generated 
                  2.  before being transmitted the entire packet is encrypted
                  3.  the encrypted packet is embedeed within a new packet.
                        the new packet contains the IP addresses of the gateway routers on the sending networks, not the IP addresses of the sender and receiver.
