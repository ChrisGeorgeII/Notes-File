Topic 1: Logging and Auditing
******************************************************************************************

  with proper configuration systems would not run into security incidents
  
  logging and audinting involve examination of detailed information:
    Logging - the action of storing inmportant data for review at a later time
      log files can determin what happened after an incident or failure.
    Auditing - process of periodically inspecting something (computer, database, ledger, Etc.)with the goal of ascertaining the true status of an item.
              audits ensure accounts are in order and inventories match the goods on hand.
              professionals will perform audits against account activities, mermissions, settings, network activity, Etc.
  
  Accounting  - Combined process of Logging and Auditing.
    The collective process of gathering data (logging) and examining that data (auditing). sometimes used with authentication and authorization, aka AAA (Authentication, Authorization, and Accounting)
  
  Unix: Logging
    Syslog  - sub-system designed to accept error reports from varying parts of the operating system and journal the events to appropriate log files
      standard logging facility used in POSIX (Unix, Linux, Solaris, Etc.) operating systems.
      Un*x Operating Systems (Unix OS) uses Syslog (System Log) as the primary logging system
        user may not beable to write but any legitimate user can read the logs.
    Syslog Categories
      syslog accepts error and event reports from:
                   Kern  - Kernal messages
                   User  - Regular user processes
                   Mail  - Messages relating to the mail system
                    Lpr  - Messages from the line printing system
                   Auth  - Activity related to requesting name and password
                 Daemon  - Background process that fulfil requests
        Local0...local7  - Local facilities defined by administrator
                console  - Messages directed to the system console
                   cron  - Messages from the cron system schedular
    Syslog Priorities
      events that are recorded by Syslog are assigned a priority, there are 8 priorities:
          emerg  - Emergency condition that needs to be addressed immediately. Ex. System Crash
          alert  - Condition that should be corrected immediately. Ex. Corrupted System Database
           crit  - Critical condition that indicates a failure in the primary system and should be corrected immediately
            err  - Error, not urgent but needs to be resolved
           warn  - Warning, not an error but an indication that an error is about to occur if not action is taken.
         notice  - not an error, but something that needs to be handled in a special way
           info  - informational message usually no action is required
          debug  - messages useful to developers for debugging
    Syslog Configurations
      Syslog fonfiguration is consistent with other files in Unix OSs and can be performed through the editing of the /etc/syslog.conf file. 
        Can direct mesages to any number of locations using syslog.conf (files, networking addresses, the console (commandline)
      The astrix in Un*x is the waldcard (*) - informs the Syslog system to route all messages of all priority security related incidents to the log file located at /var/log/security
        You'll want to log events to a file, typically /var/log/directory.
        its good idea to direct log info to a central logging server.
  
  Unix: Securing Log Files
    Copying log information from Un*x system to central log server:
      in syslog.conf file users can direct traffic to another IP addressed
        specify @<IP address> as the device, the local Syslog system will forward the events generated from that part of system(Kernel, User, Apps, Etc.) to a central logging server.
          Syslog will send using UDP on port 514 or 512

Topic 3: Authentication
******************************************************************************************

  Authentication  - the process of verifying the true identity of a computer user. 
    ensuring someone trying to acces a system is who they clame to be, through combination of Username, passwords, and/or multi factor authentication
      attackers might gather employee names or usernames through tactics like dumpster diving or browsing company websights
        when they try to log in they are stoped at the authentication stage, needing the correct passwords.
  Types of Authentication
    authentication typically works by relying on something the user HAS, sometheing the user KNOWS, and/ or something the user IS.
      Has, Possession Factors  - schemes may rely on the user to produce some physical item. this physical item is usually some kind of token or smart card, user provides their identity.
      Knows, Knowledge Factors - most comminl way of authenticating users are paswords. something the user knows may have documented drawbacks Ex. writing passwords down on desk. also passwords might be easy to guess.
      Is, Inheritance factors  - Biometrics are traits that are uniques to each person, fingerprints, retinal scans, voice inflection, Etc. these items cannot be lost and are difficult to forge.
  Managing Authentication
    most organization deploy ecntralized authentication servers in order for the computers on the network to authenticate users.
      critical when computers in network dont have primary owner/user.
      admin would need to mirror the user account information on each computer
      manage authentication requests in a secure manner: Requests and responses must be kept secret, and Requests and responses cannot be easily forged or faked.
  Kerberos Authentication
    a network running Kerberos as its default authentication protocol featers Authentication Server, Ticket Granting Server, and Service Server
      some implementations may feature all of these "servers" operating on the same actual computer.
    Kerberos Tickets:
      computers on a network running Kerberos typically exchange cryptographically secured pieces of data (Tickets) with a start and expiration time.
      when a user needs to manipulate or interact with something stored on a server, rather than requesting the user's credentials, the remote server requests proof as a ticket that the user has been authenticated.
        Tickets use Cryptography
        tickets are granted by the Ticket Granting Server. the Service Server accepts tickets as input and grants access to whatever resource is being requested.
    Kerberos Basic Steps:
      steps taken to authenticate in a Kerberized environment:
        1. Client requests an authentication ticket (TGT) from Key Distribution Center (KDC)
        2. the KDC verifies credentials and send back an encrypted TGT and session key.
        3. TGT is encrypted using the Ticket Granting Service (TGS) secret key.
        4. client stores the TGT and when it expires the local session manager will request another TGT.
      steps taken if client is requesting access to a service or other resource on the network:
        5. Client sends the current TGT to the TGS with the Service Principal Name (SPN) of the resource the client wants to access.
        6. KDC verifies the TGT of the user and that the user has access to the service.
        7. TGS sends a valid session key for the service to the client.
        8. Client forwards the session key to the service to prove the user has access, and the service grants access.
  Disadvantages of Kerberos
    because tickets can expire, its important that systems on the network have times nad dates synchronized.
    because kerberos servers control access to network resources, failure of any 3 components will result in network resources not honoring login and access requests
    kerberos is the main authentication scheme used in Windows Active Directory, MacOS X, and Red Hat Linux.
  Other Authentication Protocols
    where Kerberos would be considered overkill:
      RADIUS - Remote Authentication Dial-In Service - designed for dial-up netowrking, used in environments where users conect for short periods, including many wireless networks.
        provides centralized authentication services that can be easily deployed over wireless networking equipment
          in a RADIUS system, the client and server share a secret used to encrypt communications.
            after login info is transmitted, rRADIUS server uses other authentication protocols (EAP) to complete authentication process, as Radius server and User database serer are often separate.
          when implementing RADIUS and EAP for network authentication, ensure that security best practices are followed to protoect user credentials and prevent unauthorized access.
          organizations should consider condiguring robust encryption, certificatie validation, and integrating Multi-Factor Authentication (MFA) and exploring passwordless stratigies.
            enhance security by reducing reliance on traditional passwords and adding layers of identity verification, especially in environments wher RADIUS and EAP are used to autheintacate users across wireless and VPN connections.
      EAP - Extensible Authentication Protocol (EAP) - a flexible framework commonly used in wireless network to negotiate authentication parameters between clients and servers.
        EAP suppors a variety of methods (EAP-MD5, EAP-TLS, and PEAP) to strengthen security within its framework.
          organizations should integrate Multi-Factor Authentication (MFA) and passwordless strategies directly into the chosen EAP method.
            Ex. EAP-TLS can be enhanced by requiring a 2nd factor like biometric or hardware token, while PEAP can support passwordless authentication by leveraging certificates or device-based credentials.
              incorporating MFA and passwordless into EAP provides a more resilient authenticaitonprocess, reducing reliance on passwords and mitigating risks associated with credential theft.
  Attacks using Password Hashes
    usernames and passwords provide a easyer and more direct access to systems. attackers could exploiting technical flaws that are present on the software.
    well-Known attacks against passwords:
      Sniffing
        sniffing attacks are not specific to passwords, can be used to attack confidentiality and any data traveling over the network.
          old systems using simple authentication protocol transmitted the usernames and passwords over the netwrok in cleartext.
            attackers with network access can sniff the password while it traveled the netwrok to the authentication server
      Rainbow Attack - involves taking a password hash and comparing that hash to a set of rainbow tables.
        Rainbow Tables - Contain every possible hash that can be output by the hashing algorithm
        Hash - a value that represents a data stream, as produced by a hash function which takes some data as input and performs a series of mathematical operations on the data to produce a unique output.
          when attackers gain access to a password hash, they search the rainbow table and find the matching hash. verifying that they discovered the correct hash being used.
      Replay Attack - category of network attack where the attacker detects a data transmission and fraudulently has it delayed or repeated, carried out by the sender or by malicious entity, who intercepts the data and retransmits it.
        Replay attacks help attackers gain access to a netwrok an gain information which would not have been easily accessible or complete a duplicate transaction.
        Replay Attacks Authentication
          Replay attacks also known as Playback Attacks
          when valid users authenticate themselves they enter a password, its then hashed to some output. the hashed value is transmitted to the login server as proof that users are who they claim to be.
          attackers can retransmit the hash, the authentication server has no proof that the valid user is using that computer other than the password hash. 
            some incorporate random values which cannot be predicted into the hash (salt), causing the hashes to be different each time making playback attacks difficult.
      Pass-The-Hash - credential theft and lateral movement technique.
        an attacker can abuse the challenge-and-response nature of the NT Lan Manager (NTLM) authentication protocol to authenticate as a user with only NTLM hash of the user's password.
          attacker can use the compromised account without plaintext password. hashes normally change when password is changed, granting the attacker significatnt time to abuse the compromised user.
          
Topic 4: Authorization
******************************************************************************************
Authorization happens after authentication
  once user proves who they are, authorization determins what they are allowed to do. ensuring users can only access resources or perform actions appropriate to their roles or responsibilities.
  
  Authorization Systems 
    Authorization determines what an authenticated user is allowed to do (access to files, Resources, Services, or system functions based on Policies, Roles, or Access control lists.
    
    authorization supports:
      Confidentiality - ensuring users only see what they're permitted to.
      Integrity - Preventing unauthorized actions that could modify or corrupt data.
      Availability - preventing misuse of overuse of system resources that could cause service disruptions.
    
    Models of Authorization
    most OS manage authorization Locally or through a centralized control server via Authorization models:
      RBAC: Role-Based Access Control - Access Control Model that determines what resources and functions a user can perform based upon the requirements of the user's position within the organization.
          permissions include Read, write, and execute.
      MAC: Mandatory Access Control - Access Control Model (Military Settings) that determines the user's access rights based upon rank or position within organization.
        Access Levels include Unclassified, Secret, and Top Secret.
      EAC: Electronic Access Control - security control system used to physically manage entry and exit into secure areas of office or work site.
      DAC: Disretionary aCCESS Control - Access Control Model that uses a complete list of resources with mermissions that determine wht users have access to them.
  
  Discretionary Access Control
    in a DAC system, each asset has an Access Control List (ACL), defining which users or groups that contain broader entriesthat apply to lart portions of the population
      Ex. Windows OS ACLs typically contain an entry called "Everyone" refering to all known users.
  
  Electronic Access Control (EAC)
    Technology and Biometrics require user to validate access before entering. entry can be validated by Smart Card, Smart Badge, Keypad entry, Biometric Check
      for Exiting EAC can be configured in 2 systems:
        Free exit: no requirement for passing out of the secure area. Electronic Access Control System detects someone aproching an exit and unlocks the door or has a release button allowing people to leave.
        Controlled exit: same security is used for travel in both directions. by law these systems must be set up to allow people to exit if system fails or power goes out.
  
  Mandatory Access Control (MAC) - security access control that is centrally controlled by a security policy administrator.
    user with Secret clearance would be prevented by the system to access a file that was classified Top Secret.
  
  Role-Based Access Control (RBAC) - focuses on users' job functions and the assets they need to use in order to perform their job
    Permissions - ability to perform a specific action on a specific asset. 3 commonly seen permissions:
      Read: analogous to access, this permission enables a user to examine the contents of an asset
      Write: This Permission enables a user to modify an asset in some way.
      Execute: this permission enables a user to use a particular asset.
    Roles - defined as a collection of mermissions, logically grouped to allow a user to accomplish a task. similar to a job title or function in an organization.
    Users - analogous to users in all other access control systems. individual members of an organization.
      users have roles assigned to them, by assigning roles to users instead of the other way around, flexibility is maintained.
        each role can be assigned to multiple users
        each user can have multiple roles assigned to them
        each role can hav multiple permissions assigned to it
        roles may conflict with other roles.
      RBAC include a role hierarchy, indicating which roles should override in the event of a conflict. RBAC is currently in wide use. 
      softare packages that provide support for RBAC; Oracle Database systems, Microsoft Active Directory (windows), AP.
  
  Access Control Lists
    most OS use Access Control Lists (ACLs) a list of users who can access a particular resource (file, folder, Etc.) as well as the actions there allowed to take (Read, Write, Change Permissions, Etc.)
    every object in an OS has an ACL
  
  Directory Services - Refers to a database that stores users, apaswords, and related attibutes. 
    2 comon types of Directory Services in networks are:
      Active Directory (AD)
    Note: directory means listing of users and attributes, similar to telephone book. not the file system structure used to organize data.
      Lightweight Directory Access Protocol (LDAP) - protocol for querying and intracting with user databases, the preferred database for non windows networks.
      in Unix-like environments database of user information may be stored in a variety of ways without directly impacting the LDAP.
      LDAP refers to the protocol for communicating with the server, or the server itself.
      LDAP organizes records into Hierarchy known as a tree. each tree has a node (root) with each sub-node (called "Leaves" or "Entries") logically related to its preceding node.
        each entry represents a object (user). Attributes can be associated with objects (name, Email, Password, Contact information)
      LDAP transmits in cleartext, remedied by utilizing LDAP over TLS; (remember to specify this in config settings)
        Simple Authentication and Security Layer (SASL) has been proposed as a solution to this problem
          LDAP is a protocol any OS can use it as authentication service, provided the OS can "speak" to LDAP protocol.

Topic 4: Honeypots
******************************************************************************************
  Honeypots - a computer or network that has purposefully been left open to attack. describes both single workstations that ar edeployed to monitor hackers as well as entire networks. (honeyNet)
  
  Honeypots: Inviting Trouble
    honey pots are loaded with monitoring and logging information and will capture every "fingerprint" left behind by a potential intruder.
      allowing a system administrator to monitor attackers and observe their activities, allowing admin to better focus on defence basen on what the attackers are trying these days.
        admin can take information and attempt to pursue law enforcement.
    Resource Demands and Risks:
      Honey Pots require resources: system administrator's time and energy, Network Bandwidth, Computing Resources invested into setting up the honeypot.
        should be segregated from all of the prduction systems on the network.
        Be sure dusnt have any kind of elevated trust or permission with other parts of network; attacker may be able to use as launching pad for other atacks
  
  Honeypots: Bating the Trap Scenarios:
    Ex. 1:  - unpatched system, block it off from rest of network, put it out there to be compromised:
                admin who stay up to date with hacking stratigies will want to use this. this is an academic exercise since none of the observed activites are likely to be applicable to the other systems on network.
    Ex. 2:  - Exact replica of production system on network; give replica no responsibilities. traffic that arrives at the replica system/network must be malicious.
                an email server handling messages will have difficulty sorting malicious activity from legitimate traffic.
                admin may wish to place a replica on network, running same software. because system has no responsibilities, traffic that reaches it can be assumed to be malicious.
  
  Developing a Honeypot
    Enable Logging and secure the Standard Log Files, along with other logging tools
      Ex. logging provided by OS will not give a packet-by-packet view of network traffic like packet sniffer (e.g. Ethereal/wireshark) would.
    if attacker deduces there interacting with a honeypot and not a production system, thell probably resume attack on real systems.
      monitoring software installed on local systems are difficult to hide if the attacker can access the process table.
      Honeypot Deployment, keep in mind:
        Gather and secure information you are after.
        Ensure Honeypot cannot be used against you by an attacker.
        Unless you are going pure research, try to configure a honeypot exactly like production servers to maximize data you gather.
        ensure that your honey pot cannot be easily identified.
  Advantages of Honeypots
    a distraction to attackers allowing admin to monitor activities of attackers.
    if attackers are currently compromising your honeypot, they arnt compromising production systems.
    effectively another layer of defense.
    Ex. attackers seeking to utilize honeypot as a mail relay (spamming) might tighten the egress filtering on network traffic leaving the network.
        admin might also pursue criminal or civil action against the attacker using data gathered.
          ensure data is gathered and handled appropriately so it will be admissible in court.
  Disadvantages of Honeypots
    Not "set it and forgetit" devices, must continually be monitored. if admin dont look at log files, no information has been gained.
    Must maintain hardware. must apply patches. 
    If honey pot is to assess current defenses, than data may not be useful if honeypot doesnt mirror the production system.
    honeypots residing on network can become a liability if attackers are able to use it as a launching pad for other attacks.
      regulate its ability to reach other systems on the network. obtain approval from executive management or legal in order to limit liability should an attack occure.
